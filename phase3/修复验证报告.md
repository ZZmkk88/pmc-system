## 2. 每个修复项：问题、改法、复现与实测

### P0-2 坏请求卡死写库（最高优先级）

- **问题**：`POST /api/purchase` 传 `items[0].qty="x"` → 500，之后所有写接口（入库、登录、导入）全 500，直到重启进程。
- **根因**：`create_purchase` 里 `float(it["qty"])` 抛 `ValueError`，但只 `except sqlite3.IntegrityError: conn.close()`，**没有 `except Exception: rollback`、没有 `finally: close`**；连接带着未提交写事务泄漏，SQLite 的 RESERVED 锁不释放。
- **改法**（`app.py`）：
  - `close_quietly()`（85 行）+ `_REQ_CONNS`（请求级连接登记）；`auth_middleware`（100 行）在 `finally` 里统一 `rollback` + `close` 本请求开过的连接——就算某个接口忘了关，也不会把锁留到下一个请求。
  - `get_conn()`（140 行）：`sqlite3.connect(DB_PATH, timeout=5.0)` + `PRAGMA busy_timeout=5000`。
  - `db_tx()`（157 行）上下文管理器；全局 `@app.exception_handler(Exception)` 返回 500 JSON、`OperationalError` 且 locked/busy → 503。
  - 所有写接口改成 `try: … commit / except: rollback / finally: close`（采购、申请、库存、生产、销售、导入、合并、MRP 生成等，逐个见下）。
- **实测**：`qty:"x"` → **422** `{"detail":"明细数量必须是数字，收到：'x'"}`；紧接着入库 200、登录 200；模板回导 200（此前 500 是锁导致）。
- **回归**：`test_fixes.py::test_bad_qty_then_write_ok`、`test_template_reimport_ok`。

### P0-3 MRP 口径

- **问题**：MRP 用“现有 + 在途”，没减“已分配/冻结”；先建生产单占料后跑 MRP，净需求仍按全量算，会少买料。
- **改法**：`run_mrp`（1985 行）净需求改为 `gross - get_available(child, warehouse, company) + safety`，结果新增 `available` 字段；权限 `采购 view` + 范围校验。
- **实测**（2026-10-19 临时库复现，脚本 `check_mrp_net2.py`）：RM-001 现有 120、已分配 100、可用 20、安全库存 20，销售单毛需求 100 → MRP 返回 `gross=100, onhand=120, available=20, safety=20, net=100`，即 `100 − 20 + 20 = 100`，与库存/看板/补货同一口径。对照：同一组数字若按修复前的“现有量”口径会算成 `100 − 120 + 20 = 0`，正是这次要修的偏差（旧审核报告里记的 net 0 是修复前的结果，不是修复后的）。
- **回归**：`test_mrp_net_uses_available`（net = gross − available + safety 且含 available 字段）。

### P0-4 权限与数据范围

- **问题**：`one_available`、`dashboard`、`list_audit_log` 等无 `x_user`/`require_perm`/`check_scope`；`resolve_user` 对空 `x_user` 默认 `"admin"`；keeper 直接传零件号能看别家公司库存，看板把别家公司的缺料/补货也扫出来。
- **改法**：
  - `one_available`（1699 行）补库存 view + 按**零件自身公司**校验（`company_code or p["company_code"]`）；`list_available`（1675 行）同样按公司过滤。
  - `dashboard`（2908 行）补报表 view；parts / 生产单 / 采购单按 `allowed_companies` / `allowed_warehouses` 过滤（SQL `IN`），可用量走 `available_in_scope()`（975 行）。
  - `list_audit_log`（4053 行）只允许“系统管理员/审计员”。
  - 逐个补权限：`list_ledger`/`trace_stock`（库存 view）、`bom_explode_api`（零件 view）、供应商黑名单/审批（供应商 edit/approve）、销售改/删（销售 edit/delete）、销售转生产（生产 create）、MRP 三个接口（采购 view/edit/create）、申请单/转采购/合并/从 MRP 生成（采购 create/edit + 范围）、`excel_export`（报表 view）、`excel_import`（按导入种类映射模块 create）。
- **实测**：keeper 读 COMP-T2 零件 → **403**；worker 看审计日志 → **403**（auditor 200）；worker 调 MRP → **403**；keeper 看板不再出现别家公司补货；admin 全量正常。
- **回归**：`test_one_available_scope`、`test_dashboard_company_isolation`、`test_audit_log_permission`、`test_worker_mrp_forbidden`。

### P1-1 单号并发

- **改法**：`next_doc_no`（307 行）`BEGIN IMMEDIATE` + 同事务读号/更新；locked/busy 重试 3 次（间隔 50ms），仍失败 503。
- **实测**：8 线程并发取 PO 号 → 8 个不重复号（回归 `test_concurrent_doc_no`）。

### P1-2 税率不再写死

- **改法**：`create_requisition`（2160 行）、`convert_requisition`（2286 行）、`purchase_from_mrp`（2477 行）按零件档案 `tax_rate` 计算；`purchase_from_mrp` 建单时把 `subtotal_amount` / `tax_amount` 拆开存（修“未税金额=含税金额”）。
- **实测**：9%/6% 税率用例按档案税计算，合计 = 未税 + 税额。

### P1-3 Excel 部分列导入

- **改法**：`excel_import`（3209 行）parts 分支由“整行 UPDATE 12 列”改为**只更新 Excel 里真正出现的字段**（固定字段白名单，`name` 始终更新）。
- **实测**：只含“编码 + 安全库存”两列的表导入后，单价/税率/提前期保持原值（回归 `test_excel_partial_columns`）。

### P1-4 列名别名

- **改法**：`COLUMN_ALIASES` 增补：`订单号/订单编号/采购订单号/销售订单号/生产订单号`、`产品/产品名称/产品型号`、`需求数量/需求数/需求量/建议数量/补货数量/到货数量`、`在制/在制品/在途数量`、`跟进人/采购员/经办人`、`交货日期/要求交期`、`零件号/物料号/仓库名称/库房/库位号/批号/采购提前期/生产提前期/安全存量/物料说明`。

### P1-5 库位/批次（部分）

- **改法**：`DEFAULT_LOCATION` / `DEFAULT_BATCH` 从环境变量 `PMC_DEFAULT_LOCATION` / `PMC_DEFAULT_BATCH` 读（默认 `A区-01` / `BATCH-20261019`）；`purchase_receive`（2597 行）用请求里的 `r.batch` / `r.location`，`stock_in`/`production_complete` 允许显式传批次。
- **未完成**：仓库/库位主数据表（库位下拉、按仓库配置默认值）没有做，原因是《修复计划》把它列为“配置或仓库主数据”，属新增模块，建议下一阶段做（见 §4）。

### P1-6 完工同事务

- **改法**：`production_complete`（2879 行）不再“先 `UPDATE 状态` commit/close、再 `adjust_stock` 另开事务”，改成同一个事务：置“已完工” + 成品入库 + 写库存流水一起 commit，异常 rollback。
- **实测**：完工后状态“已完工”且 FG-001 库存 +1 同时成立（回归 `test_production_complete_atomic`）。

### P1-7 BOM 版本

- **改法**：`_version_key`（1053 行）正则取数字后比较（V10 > V9）；`resolve_bom_version`（1060 行）取 `effective_date <= 今天` 的最新生效版本，一个都没有才回退最新版本。

### P1-8 数量/金额强校验

- **改法**：`num_field()`（177 行），非法值 → **422** + 中文字段名（`明细数量必须是数字，收到：'abc'`）；采购明细 qty/price/tax、库存出入库/调拨/盘点/冻结、生产单 qty、申请单明细全部走它。
- **实测**：`qty:"abc"` → 422（不再 500）；空 body → 400；负数/0 的“必须大于 0”字段 → 422。

### P1-9 首改密

- **改法**：前端登录响应 `must_change_password=true` 时**直接切“首次登录，请先改密码”卡片**，不改密进不了系统；改密后旧 token 全失效，回到登录页。
