## 5. 设计取舍（有意为之，不是遗漏）

- **登录是演示版**：单服务 + Token 查库，无 HTTPS 强制、登录限流、Token 刷新、SSO；正式需换服务端鉴权（见 README 警告）。
- **补货目标多留一份安全库存**：目标库存 = 安全库存×2 + 提前期用量，是演示版保守策略；正式使用时可按公司策略把系数改成 1（即目标 = 再订货点）。
- **补货需求归零是正常现象**：补货采购单生成后，在途量计入可用量，可用量高于再订货点，需求暂时消失；到货后若仍不足会再次出现。
- **助手不用大模型**：规则解析可解释、可复核，查不到就说没找到；语音输入未做（本阶段是文字输入框，浏览器语音识别需 HTTPS + 麦克风权限，后续可加）。
- **MRP 分组行为变化**：从 MRP 生成采购单现按推荐供应商分组，同一批需求由旧的 1 张单（1380.86）变为 2 张单（1316.45），更便宜但单数变多，是推荐生效的预期结果，不是回归。
- **前端仍是简单单页**：建销售单 / MRP / 采购到货 / 生产领料等“做单”动作走接口（见《怎么用.md》curl 步骤），未做完整表单页；正式版可按此接口补表单。
- **零库存 + 零需求 + 零安全库存的成品不算需要补货**：避免 FG-002 这类还没投产的成品被误报。
