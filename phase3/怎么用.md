# PMC 系统第三阶段《怎么用》

> 中文 + 大白话。目标：不用看代码，照着点就能跑通一次完整流程。
> 界面说明：本阶段前端是“简单中文网页”（登录 + 看板 + 助手 + 补货 + Excel 导入 + 快捷查询），
> 建销售单 / MRP / 采购到货 / 生产领料这些“做单”动作目前走接口（下面给 curl 命令，复制粘贴就能用）。
> 截图文字描述：每一步都写了“你会看到什么”，对着看就行。

## 一、怎么启动

### 方法 A：本地启动（推荐，先用这个）

1. 打开终端，进入目录：`cd ~/workspace/pmc/phase3`
2. 建虚拟环境并装依赖（第一次才需要）：
```bash
python3 -m venv.venv &&.venv/bin/pip install -r requirements.txt
```
3. 启动服务：
```bash
.venv/bin/uvicorn backend.app:app --reload --port 8000
```
4. 浏览器打开 http://localhost:8000
- 你会看到：标题“PMC 系统 第三阶段”，下面一个“登录”卡片（用户名/密码输入框 + 登录按钮）。

### 方法 B：Docker 启动

```bash
cd ~/workspace/pmc/phase3
docker compose up --build
# 浏览器打开 http://localhost:8000，和方法 A 看到的一样
```

### 怎么确认服务活着

浏览器打开 http://localhost:8000/health，会看到 `{"ok":true,"msg":"PMC 第三阶段运行正常"}`。

## 二、怎么登录

1. 在登录卡片里，用户名填 `admin`，密码填 `admin`，点“登录”。
- 你会看到：登录卡片下方出现“登录成功”，页面展开“当前用户：admin（系统管理员）”，并出现一个黄色标签“首次登录，请先改密码”。
2. 改密码（第一次必须做）：在“旧密码”填 `admin`，“新密码”填你自己的密码（至少 6 位），点“改密码”。
- 你会看到：“密码已修改，请用新密码重新登录”，页面回到登录状态；之后用新密码登录，黄色标签消失。
3. 其余种子账号（密码 = 用户名）：`manager / manager`（采购经理）、`director / director`（采购总监）、`buyer / buyer`（采购员）、`keeper / keeper`（仓库员，仅主仓）、`finance / finance`（财务）、`auditor / auditor`（审计员，只读）、`worker / worker`（生产员）。
4. 退出点“退出登录”。

> 下面接口演示用的 curl 命令需要 Token。先取 Token（把 `你的密码` 换成你改后的密码）：
> ```bash
> TOKEN=$(curl -s -X POST http://localhost:8000/api/auth/login -H 'Content-Type: application/json' -d '{"username":"admin","password":"你的密码"}' | python3 -c "import sys,json;print(json.load(sys.stdin)['token'])")
> ```
> 之后每条 curl 都带上 `-H "Authorization: Bearer $TOKEN"`。Token 有效期 24 小时，过期重新取。

## 三、模拟表单：先导入哪个、再点哪个、预期看到什么

模拟表单在 `~/workspace/pmc/phase3/模拟表单/`，共 4 个文件：

| 文件 | 里头是什么 |
|---|---|
| `零件模拟表.xlsx` | 空模板：表头 + 1 行示例，自己填了用 |
| `库存期初模拟表.xlsx` | 空模板：表头 + 1 行示例，自己填了用 |
| `采购模拟表.xlsx` | 空模板：表头 + 1 行示例，自己填了用 |
| `模拟数据-已填好.xlsx` | 已填好的完整数据：4 页——零件（10 条）、库存期初（10 条）、采购（1 张单 2 行）、BOM（12 条） |

### 导入顺序（在页面“Excel 导入”区操作）

已填好文件有 4 页，导入时“工作表”一栏要填对应页名（`零件` / `库存期初` / `采购` / `BOM`），“种类”下拉选对应的：

| 第几步 | 种类下拉 | 工作表填 | 点什么 | 预期看到什么 |
|---|---|---|---|---|
| 1 | 零件 | 零件 | 选文件 → 上传导入 | 返回 `imported: 10`；点“零件列表”能看到 10 条：小夜灯 FG-001、台灯 FG-002、电路板组件 SUB-001、外壳/LED灯珠/电池/开关/电路板/灯罩/灯杆 |
| 2 | 库存期初 | 库存期初 | 选文件 → 上传导入 | 返回 `imported: 10`；助手问“查外壳还剩多少”，回答“现有 50” |
| 3 | BOM | BOM | 选文件 → 上传导入 | 返回 `imported: 12`；台灯 FG-002 配方共 6 条（种子 4 条 + 新增灯罩/灯杆 2 条） |
| 4 | 采购 | 采购 | 选文件 → 上传导入 | 返回 `imported: 1`；生成采购单 PO-DEMO-001（灯罩 10 + 灯杆 10，含税 113）；助手问“查灯罩还剩多少”，回答“在途 10” |

> 注意：导入是“覆盖式”写入——库存按“零件 + 仓库 + 库位 + 批次”定位，同批次的数量会被写成表中的数（不是累加）。采购导入时同单号重复导入会跳过并提示，避免重复建单。
> 空模板用法：把模板文件复制一份，按表头填自己的数据（表头支持别名，如“物料编码”也认作零件编码），再按上表导入。

## 四、按顺序操作：完整流程（用已填好的模拟数据）

> 下面“做单”步骤用 curl（复制粘贴即可）。每一步都写了预期结果，对不上就停下来看返回的错误信息。

### 第 1 步：查库存（页面助手）

- 在助手输入框输入 `查外壳还剩多少`，点“问助手”。
- 预期：`外壳（RM-001）：现有 50，在途 0，冻结 0，可用量 50，安全库存 20，状态。`

### 第 2 步：下销售单（小夜灯 100 个）

```bash
curl -s -X POST http://localhost:8000/api/sales -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' -d '{"order_no":"SO-DEMO-001","customer":"模拟客户","product_code":"FG-001","qty":100,"due_date":"2026-12-31"}'
```
- 预期：`{"ok":true,"order_no":"SO-DEMO-001"}`。

### 第 3 步：跑 MRP（自动算缺啥料）

```bash
curl -s -X POST http://localhost:8000/api/mrp -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' -d '{"sales_order_no":"SO-DEMO-001"}'
```
- 预期净需求：外壳 70（= 毛需求 100 − 现有 50 − 在途 0 + 安全库存 20）、LED灯珠 80（100−40+20）、电池 90（100−30+20）、开关 60（100−60+20）、电路板 95（100−25+20）。

### 第 4 步：MRP 一键生成采购单（自动按推荐供应商分组）

```bash
curl -s -X POST http://localhost:8000/api/mrp/generate -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' -d '{"sales_order_no":"SO-DEMO-001"}'
```
- 预期：生成 2 张采购单。SUP-001 组（灯珠 80 + 电池 90 + 电路板 95）含税 902.87；SUP-002 组（外壳 70 + 开关 60）含税 185.32。记下返回的两个单号（形如 `PO-2026-0001`），后面到货要用。
- 页面验证：点“采购单”，能看到这两张单，状态“已下单”。

### 第 5 步：采购到货（每张单、每个零件逐条收）

对第 4 步的每张采购单、每个零件各调一次（把 `单号`/`零件编码`/`数量` 换成实际的）：

```bash
curl -s -X POST http://localhost:8000/api/purchase/receive -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' -d '{"order_no":"单号","part_code":"零件编码","qty":数量}'
```
- 预期：每条返回 `"status":"部分到货"` 或 `"全部到货"`；一张单的零件全部收完后，状态变“全部到货”。
- 收完后助手问“查外壳还剩多少”，预期现有变成 120（期初 50 + 到货 70）。

### 第 6 步：建生产单 + 领料 + 完工

```bash
# 生产员账号的 Token（生产单要用 worker 身份，默认密码 worker）：
WORKER_TOKEN=$(curl -s -X POST http://localhost:8000/api/auth/login -H 'Content-Type: application/json' -d '{"username":"worker","password":"worker"}' | python3 -c "import sys,json;print(json.load(sys.stdin)['token'])")
# 建生产单
curl -s -X POST http://localhost:8000/api/production -H "Authorization: Bearer $WORKER_TOKEN" -H 'Content-Type: application/json' -d '{"order_no":"MO-DEMO-001","product_code":"FG-001","qty":100,"sales_order_no":"SO-DEMO-001"}'
# 领料（扣库存）
curl -s -X POST http://localhost:8000/api/production/consume -H "Authorization: Bearer $WORKER_TOKEN" -H 'Content-Type: application/json' -d '{"order_no":"MO-DEMO-001"}'
# 完工（成品入库）
curl -s -X POST http://localhost:8000/api/production/complete -H "Authorization: Bearer $WORKER_TOKEN" -H 'Content-Type: application/json' -d '{"order_no":"MO-DEMO-001"}'
```
- 预期：领料返回 5 种原材料各扣 100；完工返回 `"status":"已完工"`；助手问“查小夜灯还剩多少”，预期现有 100。
- 领料后各原材料现有：外壳 20（120−100）、灯珠 20、电池 20、开关 20、电路板 20。

### 第 7 步：看板 + 补货 + 助手（页面点一点就行）

1. 点“刷新看板”：看板有 5 块——智能补货建议、缺料预警、拖期采购、供应商拖期排行、生产缺料；红=有问题，黄=预警，绿=正常。
2. 点“只看需要补货的”：领料后 5 种原材料可用量都是 20，低于再订货点（日均用量 3.33 × 提前期 7 + 安全库存 20 = 43.33），会显示建议补货各 44 个（目标库存 63.33 − 可用量 20 = 43.33，向上取整 44），并给出推荐供应商。
3. 点“补货一键生成采购单”：按推荐供应商分组生成 2 张采购单（SUP-001 组 437.54、SUP-002 组 119.33）。生成后看板补货块归零（在途已覆盖，是正常现象）。
4. 助手再试几句：`哪些料需要补货`、`外壳找谁买最便宜`、`采购单 PO-2026-0001 到哪了`（单号换成你实际的）。
5. （可选）台灯演示：销售单台灯 FG-002 × 10 再跑 MRP，会看到半成品电路板组件需生产 10，而灯罩净需求 0（现有 20 + 在途 10 已够用）——说明 MRP 会把“库存够的”过滤掉，只算真正缺的。

## 六、常见问题

- **接口返回 401**：Token 过期或没带。重新登录取 Token；curl 记得带 `-H "Authorization: Bearer $TOKEN"`。
- **导入返回“表头未识别”**：表头写错了。下载系统模板按表头填，或用已填好文件对照；表头支持别名（如“物料编码”=“零件编码”）。
- **导入库存后数量不对**：库存导入是覆盖式（同零件+仓库+库位+批次写成表中数），不是累加。想累加请走“采购到货”或“库存入库”接口。
- **MRP 净需求和预期不一样**：先查在途（未到货采购单）和可用量——MRP 公式是 `净需求 = 毛需求 − 现有 − 在途 + 安全库存`，在途的采购单会抵掉一部分需求。
- **手机打不开 / 排版乱**：用手机浏览器打开同一地址（电脑和手机要在同一局域网），页面是响应式的；不要用电脑端把窗口缩到很小来模拟，手机实测为准。
